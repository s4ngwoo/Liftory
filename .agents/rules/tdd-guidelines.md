# Test-Driven Development (TDD) Rule

Liftory 프로젝트의 모든 비즈니스 로직, UseCase, ViewModel 작성 시 준수해야 하는 TDD 원칙입니다.

---

## 1. Red-Green-Refactor 사이클

1. **Red (실패하는 테스트 먼저 작성)**:
   - 프로덕션 코드 구현 전, 요구사항을 검증하는 테스트 케이스를 먼저 작성합니다.
   - 컴파일 에러 또는 Assertion 실패를 확인합니다.
2. **Green (최소한의 구현으로 테스트 통과)**:
   - 테스트를 통과하기 위한 최소한의 프로덕션 코드를 작성합니다.
3. **Refactor (아키텍처 및 품질 개선)**:
   - 테스트가 계속 통과하는 상태를 유지하면서 코드 중복 제거, 클린 아키텍처 규칙 준수, 네이밍 개선을 수행합니다.

---

## 2. 테스트 작성 가이드라인

- **경량 Fake 패턴 사용**:
  - 외부 의존성(Repository, TransactionProvider 등)은 `Fake*` 클래스를 구현하여 결정론적이고 가벼운 인메모리 테스트를 유지합니다.
- **버그 수정 시 Regression Test 작성**:
  - 런타임 오류나 로직 버그 발견 시, 해당 오류를 재현하는 단위 테스트를 먼저 작성하여 원인을 증명한 후 수정합니다.
- **테스트 통과 검증**:
  - 변경 작업 완료 전 항상 `./gradlew testDebugUnitTest`를 실행하여 100% 통과를 확인합니다.
